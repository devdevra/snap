# 스테이컷 고객 포털 화면 명세 · 기획 고도화안

기준 문서: `docs/service-plan-v2.md` · 원자료: `docs/service-plan.md` · 작성일: 2026-10-15

이 문서는 소규모 숙소 운영자가 **검토할 버전을 확인하고, 게시 가능한 파일을 내려받고, 실제 게시 여부를 남기는 흐름**을 구체화한 화면 설계안이다. 실제 구현 완료나 고객 검증 결과를 뜻하지 않는다. 함께 제공하는 디자인 이미지는 정적 개념안이며 전체 상태·상호작용의 검증 결과가 아니다. 기준 문서에 없는 UI 방식·판정 규칙·이벤트는 모두 **이번 화면 설계의 제안**이다. 계약상 기간·횟수·보관 조건은 합의된 주문 값을 사용하며 화면에서 임의로 확정하지 않는다.

## 1. 화면을 관통하는 결정

1. 첫 화면에는 ‘지금 내 차례인지’와 ‘다음 행동’이 먼저 보인다. 매출·예약 증가·활용 효과 같은 실적 지표는 넣지 않는다.
2. 고객의 콘텐츠 승인은 **특정 버전의 내용에 대한 확인**이다. 이용허락 확인, 다운로드, 실제 게시와 각각 분리한다.
3. 게시용 보관함은 **현재 선택한 채널과 목적에서 사용할 수 있는 최신 승인본**을 먼저 보여준다. 권리 미확인·만료·대체된 버전은 정상 게시 후보와 구분한다.
4. 기존 문서의 ‘제작자 1명·승인 담당자 1명·통합 피드백’ 운영 가정을 유지한다. 관리자·팀 협업·SNS 자동 게시 기능은 확장하지 않는다.
5. 상품명·가격·수정 횟수·기한은 계약과 연결한다. ‘통합 수정 1회’ 등의 내용은 해당 주문에 실제 합의된 경우에만 표시한다.

## 2. 정보 구조와 기본 동선

### 고객용 최상위 메뉴

| 메뉴 | 고객의 질문 | 포함 정보 |
| --- | --- | --- |
| 홈 | 지금 무엇을 해야 하나요? | 숙소·주문, 현재 단계, 내 다음 행동, 합의된 기한, 최근 전달 내용 |
| 검토함 | 어떤 버전을 확인해야 하나요? | 검토 요청과 처리 상태, 정확한 버전으로 이동, 통합 수정 요청·승인 이력 |
| 콘텐츠 | 어느 파일을 어디에 써도 되나요? | 게시용 보관함: 채널·목적별 파일, 최신 승인 버전, 사용 조건, 다운로드, 게시 확인 |

**버전 검토**는 검토함 또는 홈의 검토 요청에서 진입하는 작업 화면이다. **작업 정보**는 홈의 주문 범위 링크에서 여는 보조 상세로, 주문 범위·수정 조건·납기·승인자·보관 종료일·계약상 사용 조건을 보여준다. 최상위 메뉴는 **홈 · 검토함 · 콘텐츠**의 세 개로 통일한다. ‘게시용 보관함’은 콘텐츠 메뉴가 제공하는 기능 설명이다. 별도 채팅방·알림센터·성과 대시보드는 초기 범위에 넣지 않는다.

### 핵심 동선

`홈의 검토 요청 → 버전 미리보기·사실관계 확인 → 채널·이용허락 확인 완료 → 특정 버전 최종 승인 → 게시용 보관함에서 다운로드 → 고객이 외부 채널에 직접 게시 → 게시 여부 기록 → 다음 주제 재요청`

수정이 필요하면 `검토 → 통합 수정 요청 → 제작자가 새 버전 전달 → 새 버전 검토`로 돌아간다. 새 버전이 생겨도 이전 버전의 승인 기록은 유지한다.

**제안 — 다음 행동 선정 순서:** 필수 정보 보완 요청 → 현재 버전 검토 → 사용 가능한 승인본 다운로드 → 아직 확인하지 않은 게시 여부 기록. 고객이 할 일이 없으면 ‘제작 중입니다’와 합의된 다음 전달 일정을 보여준다. 단순한 지연 표시를 새 작업이나 자동 승인으로 바꾸지 않는다.

## 3. 핵심 화면 A · 홈

**목표:** 운영자가 작업 상태와 자신의 다음 행동을 한 번에 파악한다.

**기본 주행동:** `검토 시작` — 현재 검토 대기인 정확한 버전으로 이동한다.

| 표시 순서 | 요소 | 정보·행동 |
| --- | --- | --- |
| 1 | 숙소와 작업 | 숙소명, 작업명, 주문 범위 링크. 금액은 홈의 핵심 지표로 반복하지 않는다. |
| 2 | 다음 행동 카드 | ‘새 영상의 문구와 시설 정보를 확인해 주세요’처럼 구체적 요청, 해당 버전, 합의된 확인 기한, 주행동 1개 |
| 3 | 작업 진행 요약 | 준비·촬영·제작·검토·납품의 현재 위치. 진행률을 임의의 백분율로 표시하지 않는다. |
| 4 | 최근 전달 내용 | 제작자가 보낸 검토 요청·수정 처리 내용. 읽어야 하는 이유가 보이는 짧은 문장 |
| 5 | 현재 게시 가능한 파일 | 채널과 사용 조건이 맞는 최신 승인본 미리보기, ‘보관함 보기’ 보조 링크 |
| 6 | 작업 정보 | 합의된 다음 일정·승인 담당자·보관 종료일 등 확인 링크 |

**주행동의 상태별 대체안 — 제안:** 검토가 없고 내려받을 파일이 있으면 같은 위치를 `게시용 파일 보기`로 바꾼다. 제작 중이라면 강제로 클릭할 행동을 만들지 않고 담당자와 다음 전달 일정만 표시한다. 동시에 ‘승인’과 ‘다운로드’를 같은 중요도로 띄우지 않는다.

**빈 상태:** ‘아직 검토할 파일이 없습니다. 현재 초안을 제작 중입니다.’와 계약상 일정. 확인하지 않은 완료 수치, 샘플 고객의 실적, 예상 예약 증가 등을 넣지 않는다.

**화면 문구 예시:** `현재 단계: 검토 대기` / `내 할 일: 세로 영상 v2 확인` / `확인 기한: 주문에서 합의한 날짜`. 시안의 숙소·미디어·일정은 모두 예시임을 명시한다.

## 4. 핵심 화면 B · 버전 검토

**목표:** 무엇을 승인하는지 분명히 알고, 수정사항을 흩어지지 않게 전달한다.

**주행동:** `이 버전 승인` — 버튼 가까이에 콘텐츠명과 `v2`처럼 대상 버전을 함께 표시한다.

| 영역 | 필수 내용 |
| --- | --- |
| 상단 | 뒤로가기, 콘텐츠 제목, 버전 번호, 전달일, 상태 `검토 대기` |
| 미리보기 | 사진 확대 또는 사용자가 직접 재생하는 영상. 영상 규격·길이, 게시 대상 채널, 자막·문구 확인 |
| 변경 요약 | 새 버전이라면 이전 버전에서 무엇이 바뀌었는지 제작자가 적은 설명. ‘변경 없음’과 설명 누락을 구분 |
| 확인 내용 | 실제 시설·제공 서비스·문구·노출 인물 등 고객이 판단할 내용. 사용권 검토 완료를 고객 사실 확인 체크에 섞지 않음 |
| 사용 조건 | 승인 상태와 별개로 `이용허락 확인됨 / 확인 중 / 만료` 및 허용 채널·목적·기간. 권리 근거 원문이나 개인정보는 불필요하게 노출하지 않음 |
| 통합 피드백 | 전체 수정사항을 한 번에 적는 입력란, 계약에 포함된 수정 범위·횟수, 보조행동 `수정 요청 보내기` |
| 승인 영역 | 대상 버전, 승인 의미를 한 문장으로 설명, `이 버전 승인` 주행동. 필요한 이용허락이 확인되고 유효한 경우에만 실행 가능하며 성공 후 승인자·시각·버전 기록 표시 |

**제안 — 승인 직전 안내:** ‘이 버전의 화면과 문구를 확인했습니다. 게시 가능한 범위는 별도 사용 조건을 따릅니다.’를 버튼 바로 위에 표시한다. 모든 권리를 포괄 양도받았다는 식의 동의를 붙이지 않는다.

**제안 — 승인과 피드백 충돌 방지:** 수정 입력 중에는 승인 전 입력 내용을 처리하도록 안내한다. 수정 요청 제출과 버전 승인을 같은 동작으로 처리하지 않는다. 수정 요청은 제출 전 한 화면에서 전체 내용을 확인할 수 있게 한다.

**v2 기본안 — 권리 확인 후 최종 승인:** 기존 프로토타입의 ‘권리 미확인 시 승인 차단’ 규칙에 맞춘다. 권리 미확인·만료 상태에서도 고객은 미리보기 확인, 검토 의견 작성, 수정 요청을 할 수 있다. **최종 승인과 게시용 다운로드는 모두 차단**하며 `사용 조건 확인 중 · 최종 승인 및 게시용 다운로드 불가` 또는 `사용 기간 종료 · 최종 승인 및 게시용 다운로드 불가`를 표시한다. 승인·이용허락·게시의 데이터와 표시 상태는 계속 분리한다.

**승인 완료 뒤 동선:** 현재 채널에서 사용할 수 있으면 `게시용 보관함 보기`를 다음 주행동으로 표시한다. 승인 후 나중에 이용허락이 만료되거나 다시 확인이 필요한 상태가 되면 승인 이력은 보존하되 게시용 다운로드를 차단하고 이유와 담당자를 표시한다. 승인 완료 화면에서 권리 상태를 영구적인 사용 가능 보증으로 표현하지 않는다.

## 5. 핵심 화면 C · 콘텐츠 — 게시용 보관함

**목표:** 현재 게시할 채널에 맞는 파일을 선택하고 사용 범위를 확인한 뒤 내려받는다.

**주행동:** `게시용 파일 다운로드` — 선택한 파일·채널·목적에 한해 제공한다.

| 표시 순서 | 요소 | 정보·행동 |
| --- | --- | --- |
| 1 | 제목과 짧은 설명 | ‘게시할 채널을 고르면 사용할 파일을 보여드립니다.’ |
| 2 | 채널 선택 | 주문에서 합의한 채널만 제공. 해당 없음은 ‘다른 채널 사용 문의’ 보조 경로 |
| 3 | 용도 선택 | 계약이 구분하는 경우 일반 게시/유료 광고 등을 선택. 하나의 채널 허용을 모든 목적 허용으로 넓히지 않음 |
| 4 | 보조 필터 | 주제·공간·형식. 모바일에서는 접을 수 있는 한 영역에 배치 |
| 5 | 파일 목록 | 썸네일, 콘텐츠명, 최신 승인 버전, 사진/영상 규격, 사용 조건 요약, 게시 기록 |
| 6 | 선택 파일 상세 | 미리보기, 정확한 허용 매체·목적·기간, 보관 종료일, 승인 기록, 다운로드 주행동 |
| 7 | 다운로드 이후 | 외부 채널에 직접 올리는 짧은 안내와 보조행동 `게시 여부 남기기` |
| 8 | 다음 주제 | `이 원본으로 재편집 문의` 보조행동. 즉시 제작 확정·정기 결제 개시로 오해하지 않도록 안내 |

**제안 — 기본 목록 조건:** 최신 승인 버전이며, 현재 선택한 채널·목적·시점에서 필요한 이용허락이 확인되고, 계약상 파일 접근 기간 안에 있으며, **계약상 최종 전달을 위한 수납 조건까지 충족한 것**만 게시용 다운로드 후보로 보여준다. 원본 제공 권한과 최종본 다운로드 권한도 구분한다.

**제안 — 분할결제와 최종 전달:** 첫 촬영은 `50% 예약금 → 정확한 버전 승인 → 잔액 청구·수납 확인 → 최종 원본규격 파일 전달`의 운영안을 계약에 반영하는 경우에 적용한다. 여기서 최종 원본규격 파일은 합의한 최종 납품본을 뜻하며 RAW·소스·프로젝트 파일 제공 권한을 새로 부여하지 않는다. 잔액이 미수납이거나 수납 확인 전이면 **기존 승인 이력을 유지**하고 `수납 확인 후 최종 파일을 전달합니다`와 결제 상태 확인 안내를 표시한다. 고객에게 동일 버전의 승인을 반복 요구하지 않는다. 수납 확인은 수동 운영도 가능하며 실제 결제 시스템 구현은 초기 범위에서 보류한다. 디자인 시안에서 다운로드할 수 있는 예시 파일은 이미 계약상 수납 조건을 충족한 상태로 해석한다.

**제안 — 사용 보류 항목:** `사용 조건 확인 중`과 `사용 기간 종료`는 보조 영역에서 확인할 수 있게 하되 정상 다운로드 버튼을 붙이지 않는다. 사용 가능한 파일이 없으면 이유와 담당자 확인 경로를 표시한다. 과거 승인본은 이력에서 ‘v2로 대체됨’처럼 표시하며 최신 목록에 중복 노출하지 않는다.

**게시 증거 수준 — 제안:** 버전·채널·게시일이 있는 운영자 응답은 `운영자 자기신고`로 보존한다. 고객이 동의해 URL·화면을 제공하고 제작자가 확인한 경우만 `URL/화면 확인`으로 따로 표시한다. 자동 플랫폼 검증이라는 명칭은 쓰지 않는다. 8주 파일럿의 최초 게시 지표는 자기신고를 포함한 운영자 응답 기준이며, URL/화면 확인 수를 보조 지표로 함께 제시한다. 확인 불가는 성공에 포함하지 않는다.

**게시 기록 입력:** `아직 게시하지 않았어요 / 게시했어요`를 선택한다. 게시했으면 채널·게시일을 기록하고 URL은 선택 입력으로 둔다. URL이 없다는 이유로 고객의 게시 응답을 버리지 않는다. 상태는 `운영자가 게시했다고 확인`으로 표현하며 플랫폼 검증 완료나 노출·성과 측정으로 표현하지 않는다. 미게시 이유는 일정·품질·담당자·규격·기타를 선택적으로 남긴다.

**재요청 최소 입력 — 제안:** 원하는 주제, 채널, 희망 기한, 참고 콘텐츠/원본, 새로 달라진 시설·서비스. 제출은 ‘가능 여부 검토 요청’이며 제작·비용·일정은 원본과 사용권을 확인한 후 합의한다. 없는 계절·시설을 만드는 옵션이나 예약 실적 보장 문구를 넣지 않는다.

## 6. 승인·이용허락·게시 상태 전이

세 축을 각각 저장하고 화면에서도 이름을 붙인다. 하나의 녹색 배지에 ‘승인·권리·게시 완료’를 합치지 않는다. 제작 단계 및 파일 보관 상태도 별도 정보다.

### A. 콘텐츠 승인: 버전 단위

| 현재 상태 | 사건 | 다음 상태 | 고객에게 보이는 결과 |
| --- | --- | --- | --- |
| 제작 중 | 특정 버전이 검토용으로 전달됨 | 검토 대기 | 대상 버전·확인 기한 표시 |
| 검토 대기 | 고객이 통합 수정 요청 제출 | 수정 요청됨 | 요청 내용·제출일 표시, 승인 아님 |
| 수정 요청됨 | 새 버전 전달 | 새 버전은 검토 대기 | 이전 요청·버전 이력 유지 |
| 검토 대기 | 필요한 이용허락이 확인되고 유효한 상태에서 승인 담당자가 해당 버전을 명시적으로 승인 | 승인됨 | 승인자·시각·버전 표시 |
| 검토 대기 | 권리 미확인·만료 상태에서 최종 승인 시도 | 검토 대기 유지 | 최종 승인 차단, 검토 의견·수정 요청은 가능 |
| 승인됨 | 문구·음원·컷 등 변경 버전 전달 | 기존 승인 유지 + 새 버전 검토 대기 | 기존 승인을 새 버전에 복사하지 않음 |
| 구버전 승인됨 | 새 버전 승인 | 구버전은 대체됨, 새 버전 승인됨 | 최신본 명확화, 과거 승인 이력 보존 |
| 검토 대기 | 응답 기한 경과 | 검토 대기 유지 | ‘확인 기한 지남’ 표시·후속 일정 조율, 자동 승인 없음 |

‘대체됨’은 내용 승인 이력을 지우는 의미가 아닌 **최신본 관계 표시**다. 서버 판정 시점의 정확한 버전을 기준으로 승인해야 한다는 구현 규칙은 이번 제안이다.

### B. 이용허락: 소재·버전·채널·목적·시점 조합

| 현재 상태 | 사건 | 다음 상태 | 다운로드·게시 안내 |
| --- | --- | --- | --- |
| 미확인 | 필요한 권리 근거 확인 | 조건 확인됨 | 허용된 범위·기간에서만 게시 후보 가능 |
| 조건 확인됨 | 특정 채널·목적이 허용 범위 밖 | 해당 사용 불가 | 다른 채널/목적을 선택하거나 이용 범위 확인 요청 |
| 조건 확인됨 | 계약상 사용 기간 종료 | 만료 | 승인 이력 유지, 새 게시용 추천에서 제외 |
| 조건 확인됨 | 새 버전에 새 음원·인물 등 추가 | 새 버전 해당 소재 미확인 | 새 버전의 조건을 다시 확인 |
| 미확인/만료 | 근거 보완·정식 이용허락 갱신 | 조건 확인됨 | 승인·최신본·접근 기간까지 충족할 때 게시 후보 복귀 |

최종본의 이용 가능 범위는 포함 소재 중 가장 제한적인 조건을 반영한다. UI는 저작권 귀속·원본 제공·포트폴리오 게시 허락을 일반 이용허락과 섞지 않는다. **제안:** 기간 경계와 시간대는 계약 해석에 맞게 저장하고 만료 날짜를 고객에게 명확히 보여준다. 만료 시 기존 게시물의 처리까지 자동으로 단정하지 않고 계약 조건과 담당자 확인 경로를 안내한다.

### C. 게시: 버전·채널별 고객 응답

| 현재 상태 | 사건 | 다음 상태 | 해석 |
| --- | --- | --- | --- |
| 미확인 | 파일 다운로드 | 미확인 유지 | 내려받았다는 사실만 기록 |
| 미확인 | 고객이 아직 게시하지 않았다고 응답 | 미게시 | 선택적으로 미게시 이유 기록 |
| 미확인/미게시 | 고객이 게시했다고 응답 | 게시함: 운영자 확인 | 채널·게시일·선택적 URL 기록 |
| 게시함: 운영자 확인 | 고객이 입력을 정정 | 정정된 응답 | 최신 응답과 변경 시점 유지 — 제안 |
| 어떤 상태든 | 새 버전 제작·승인 | 새 버전 게시는 미확인 | 구버전의 게시 기록을 새 버전에 승계하지 않음 |

고객이 URL을 남겼어도 자동 수집·SNS 연동을 구현하지 않은 한 외부 검증 결과로 표시하지 않는다. 같은 버전의 여러 채널 게시를 한 개의 전체 게시 배지로 덮지 않는다.

### 조합에 따른 주행동 판정 — 제안

| 승인 | 이용허락 | 최신본·접근·최종 전달 조건 | 주행동 |
| --- | --- | --- | --- |
| 검토 대기 | 현재 선택 조건에서 확인되고 유효함 | 현재 검토 버전 | `검토 시작` / 검토 화면의 `이 버전 승인` |
| 검토 대기 | 미확인·만료·범위 밖 | 현재 검토 버전 | 검토 의견·수정 요청 가능, 최종 승인 및 게시용 다운로드 차단 |
| 승인됨 | 현재 선택 조건에서 확인됨 | 최신본·접근 가능·계약상 수납 조건 충족 | `게시용 파일 다운로드` |
| 승인됨 | 현재 선택 조건에서 확인됨 | 최신본·접근 가능하나 계약상 수납 조건 미충족/확인 전 | 승인 이력 유지, 최종 다운로드 차단, 결제 상태 확인 안내. 동일 버전 재승인 요구 없음 |
| 승인됨 | 미확인·만료·범위 밖 | 어떤 상태든 | 기존 승인 이력 보존, 게시용 다운로드 차단, 이유와 확인 경로 |

| 승인됨 | 확인됨 | 계약상 보관·접근 종료 | 보관 종료 안내와 계약상 내보내기 처리 상태 |

## 8. 모바일 배치와 디자인 원칙

아래 화면 배치는 제안이다. 작은 화면에서 사진을 보기 전에 상태와 행동이 묻히지 않도록 한다.

- **공통:** ivory `#f4f3ed` 바탕, forest green `#254e3a` 주요 텍스트·주행동, sage/lime `#d5e89a` 상태 강조. 숙소의 목재 질감과 자연광 사진을 넉넉하게 사용하되 작업 상태 영역은 단색으로 유지한다.
- **홈:** 상단 숙소명 → 다음 행동 카드 → 진행 요약 → 최신 파일 순서의 한 열 배치. 장식용 대형 사진이 다음 행동을 화면 밖으로 밀어내지 않게 한다.
- **검토:** 대상 버전·채널을 먼저 표시하고 전체 폭 미리보기, 변경 요약, 확인 정보, 피드백을 순서대로 둔다. 하단 승인 영역은 안전영역을 반영하고 본문·키보드를 가리지 않는다. 영상은 자동 재생하지 않는다.
- **보관함:** 채널·목적 선택을 목록 위에 두고 파일 카드는 작은 화면에서 한 열, 충분한 폭에서만 두 열로 펼친다. 필터를 가로로 계속 밀어야만 이해할 수 있게 만들지 않는다.
- **폭이 넓을 때:** 검토 화면의 미리보기와 승인/조건 영역을 두 열로 배치한다. 홈에서 불필요한 숫자 카드나 관리자 기능을 추가하지 않는다.
- **상태:** `내용 승인`, `사용 조건`, `게시`라는 명칭을 계속 사용한다. 상태는 색+텍스트로 표현한다. lime 위 흰 글씨는 사용하지 않으며 실제 렌더링에서 대비를 검증한다.
- **사진:** 시안에 가상 숙소 이미지가 들어가면 ‘가상 숙소 · 시안용 이미지’라고 표시한다. 실제 포트폴리오나 검증된 고객처럼 보이게 하지 않는다.

## 9. 접근성·입력·안전 조건

다음은 실제 포털 구현 시 적용할 제안·기본 요구다.

- 주요 조작 영역은 최소 44×44 CSS px를 목표로 하고 키보드 포커스가 분명히 보이게 한다. 페이지 제목·소제목·버튼·입력의 의미 구조를 유지한다.
- 미디어 확대·영상 재생·버전 선택·승인·수정 제출은 키보드로 조작 가능해야 한다. 사진에 필요한 대체 설명을 제공하고 검토할 영상 문구는 읽을 수 있는 텍스트로 함께 제공한다.
- 오류는 원인과 다음 행동을 입력 근처에 표시하고 화면 읽기 도구에 알린다. 성공 상태는 서버 기록 확인 뒤 전달한다.
- 기한은 ‘3일 남음’만 쓰지 않고 합의된 절대 날짜도 표시한다. 색만으로 기한 경과·사용 불가·승인됨을 구분하지 않는다.
- 피드백 작성 중 화면 이동·통신 오류가 나도 입력이 사라지지 않도록 한다. 임시 저장 여부와 범위는 구현 시 명확히 알린다.
- 숙소별 접근 권한, 파일별 안전한 링크, 승인 권한 확인은 서버에서 처리한다. 최종 승인과 게시용 다운로드를 요청할 때마다 현재 이용허락·만료 여부를 다시 확인한다. 숨긴 버튼이나 오래 열린 화면의 상태만으로 권한·사용 가능 여부를 판정하지 않는다.
- 고객 계정 비밀번호·SNS 접근 권한을 요구하지 않는다. URL은 선택 입력이며 고객의 불필요한 개인정보를 수집하지 않는다.

## 10. 최소 데이터와 이벤트

### 최소 데이터 — 기준 문서 구조를 화면에 연결

| 객체 | 최소 필드 | 필요한 이유 |
| --- | --- | --- |
| 숙소·주문 | 숙소 ID, 주문 ID, 작업명, 승인자 ID, 범위, 합의 기한, 수정 조건, 보관·접근 조건, 계약상 최종 전달 수납 조건·확인 상태 | 홈의 다음 행동과 계약 범위 표시, 최종 파일 전달 조건 확인. 수납 확인은 수동 운영 가능 |
| 콘텐츠 버전 | 콘텐츠 ID, 불변 버전 ID, 버전 번호, 참조 원본·소재, 변경 요약, 채널·규격, 전달 시각, 최신본 관계 | 정확한 검토·승인 대상 유지 |
| 이용허락 | 대상 원본/소재/버전, 확인 상태, 허용 매체·목적·기간, 근거 위치 | 게시 후보 판정·설명. 고객에게 필요한 조건만 표시 |
| 검토·승인 | 버전 ID, 피드백 내용·제출 시각, 승인자·시각, 승인 기록 ID | 요청과 승인 분리·오류 재확인 |
| 파일 | 버전 ID, 파일 ID, 형식·용량, 안전한 저장 참조, 다운로드 제공 가능 조건 | 맞는 파일 전달 |
| 게시 응답 | 버전 ID, 채널, 응답 상태, 게시일, 선택 URL, 응답자·시각 | 다운로드와 실제 게시 구분 |
| 재요청 | 주문/원본/콘텐츠 참조, 주제, 채널, 희망 기한, 변경된 시설 정보, 검토 상태 | 재설명 최소화·가능성 확인 |

**제안:** 고객 식별자는 내부 참조에 한정하고 운영상 승인 기록과 일반 사용 분석을 분리한다. 파일 URL·피드백 전문·권리 문서·게시 URL을 분석 이벤트 속성에 복제하지 않는다. 보존 기간은 계약·운영 조건에 맞춰 별도 확정한다.

### 최소 이벤트 — 모두 구현 제안

| 이벤트 | 최소 속성 | 의미·측정 한계 |
| --- | --- | --- |
| `review_opened` | 주문 ID, 버전 ID, 시각 | 검토 화면 진입. 실제 내용을 모두 보았다는 뜻 아님 |
| `feedback_submitted` | 주문 ID, 버전 ID, 요청 ID, 시각 | 통합 피드백 서버 접수. 전문은 피드백 객체에 보관 |
| `version_approved` | 주문 ID, 버전 ID, 승인 기록 ID, 시각 | 서버에서 확정된 명시적 승인. 클릭 시도와 구분 |
| `download_requested` | 버전 ID, 파일 ID, 채널·목적, 시각 | 파일 요청. 저장 완료·실제 게시로 계산하지 않음 |
| `download_delivery_failed` | 파일 ID, 오류 분류, 시각 | 전달 실패. 브라우저 로컬 저장 여부를 확인했다고 표현하지 않음 |
| `publish_response_saved` | 버전 ID, 채널, 응답 상태, 응답 기록 ID, 시각 | 운영자가 남긴 게시 응답. 외부 플랫폼 검증 아님 |
| `reuse_request_submitted` | 주문/원본 참조, 요청 ID, 시각 | 재편집 검토 요청. 유료 구매·실제 재사용으로 계산하지 않음 |

파일 검색·권리 확인 시간은 화면 진입 이벤트만으로 추정하지 않고 기준 문서의 과제 방식으로 측정한다. 유료 재편집·갱신·실제 게시비율은 주문·납품·고객 응답 기록에서 정의에 따라 산출하며 시안에 임의의 달성 수치를 넣지 않는다.

## 11. 시안 검토 기준

- 홈에서 지금 해야 할 행동과 대상 버전이 바로 보이는가?
- 내용 승인 뒤에도 현재 이용허락과 게시 여부가 각각 구분되는가?
- 권리 미확인·만료 상태에서 검토 의견·수정 요청은 가능하고 최종 승인·게시용 다운로드는 차단되는가?
- 권리 미확인·만료·구버전이 정상 게시용 파일처럼 추천되지 않는가?
- 다운로드를 게시 완료로 오해하게 하는 체크·문구가 없는가?
- 새 버전·오류·기한 경과에도 승인 기록과 수정 요청이 유실되지 않는가?
- 모바일에서 미디어·피드백·승인 버튼을 읽고 조작할 수 있는가?
- 가상 이미지·예시 데이터가 실제 제품·고객 성과로 오인되지 않는가?
