# 제작 운영자 사용 안내

[운영 관리 열기](https://staycut-snap.vercel.app/#manage)에서 숙소·작업·고객 접근과 영상 전달을 관리합니다. 운영자는 고객사 `owner`와 별도의 권한이며 현재 포털 전체 고객사에 적용됩니다. 고객의 내용 승인과 실제 SNS 게시는 별도입니다.

## 설치

기반·미리보기·운영자 업로드 SQL과 첫 운영자 배정은 기존 설치 단계입니다. 이미 설치한 프로젝트에는 `202610160003_operator_members.sql`만 추가 적용합니다. 신규 프로젝트 설치는 [Supabase 설정 안내](supabase-setup.md)를 따릅니다. 코드 배포가 운영 DB 마이그레이션을 대신하지 않습니다.

첫 운영자는 이메일 확인이 끝난 기존 Auth 계정이어야 합니다. [운영자 배정 SQL](../supabase/admin/assign-operator.sql)은 운영 권한만 부여하며 고객사 멤버십을 바꾸지 않습니다. 해당 계정으로 로그인한 뒤 화면 아래 **운영 관리**를 엽니다. 권한이 없으면 고객 작업 공간으로 돌아가는 안내가 표시됩니다.

운영 화면은 Auth 계정·비밀번호를 만들거나 초대 메일을 보내지 않습니다. 새 계정이 필요하면 먼저 Supabase Authentication에서 관리자 권한으로 만듭니다. 비밀번호·서버 키를 채팅이나 저장소에 넣지 않습니다.

## 작업 현황과 고객 관리

숙소를 고르면 검토 대기·수정 요청·승인 완료 작업과 조건 확인이 필요한 작업을 확인할 수 있습니다. 작업 목록에서 검색·상태 필터로 대상을 찾고 영상 전달이나 조건 관리로 이동합니다. 이 현황은 선택한 숙소의 작업을 기준으로 합니다.

**고객 관리**에서는 다음을 처리합니다.

- 이메일 확인이 끝난 기존 Auth 계정을 현재 숙소의 `member`로 추가합니다. 이미 배정된 계정은 추가 기능으로 덮어쓰지 않습니다.
- 고객의 활성 상태·접근 허용·접근 시작일과 종료일을 변경합니다. 날짜는 한국 시간 기준이며 시작일·종료일을 포함합니다. 고객사 멤버십과 작업 자체의 접근 조건이 모두 유효해야 파일에 접근할 수 있습니다.
- 권한 회수 확인 후 해당 숙소의 접근을 중지합니다. Auth 계정과 다른 숙소의 배정은 유지하며 승인·수정 이력을 삭제하지 않습니다. 이미 발급한 파일 링크는 최대 60초의 남은 유효 시간 동안 동작할 수 있습니다.
- 기존 작업의 지정 승인자를 같은 숙소의 접근 가능한 확인된 계정으로 변경합니다. 승인자 변경은 기존 승인 기록을 수정하지 않습니다. 담당자를 회수했다면 미완료 작업의 승인자를 다른 고객에게 다시 배정합니다.

고객 변경은 화면에서 확인한 revision과 대조합니다. 다른 운영자가 먼저 변경했으면 저장을 거절하고 입력을 유지합니다. 최신 상태를 다시 읽어 변경 내용을 비교한 후 저장합니다. 승인자 변경도 기존 담당자와 최신 버전을 다시 검사합니다. 고객 관리로 시스템 운영자 권한을 부여할 수 없습니다.

## 영상 전달

**영상 전달**에서 작업 선택 → 파일 선택 → 조건 확인 순서로 진행합니다.

1. 새 작업은 제목과 지정 승인자를 입력합니다. 기존 작업은 **새 버전 전달** 대상을 고릅니다. 현재 수정 요청이 있으면 내용을 확인하고 반영 확인을 체크합니다.
2. **게시용 원본**과 **별도 검토용 미리보기**를 선택합니다. 각각 최대 **50 MiB(52,428,800바이트)**의 MP4 또는 WebM이며 브라우저에서 재생 가능해야 합니다. 검토용은 저용량 또는 워터마크 영상으로 별도 제작합니다. 같은 파일을 이름만 바꿔 선택하면 거절됩니다.
3. 새 작업의 파일 접근 기간과 콘텐츠 사용 기간, 허용 채널·목적을 계약 내용에 맞춰 입력합니다. 기본값은 **접근 미허용·이용허락 확인 전·수납 미확인**입니다. 채널·목적 초기 선택이 이용허락 확인을 뜻하지 않습니다. 이용허락·수납은 실제 확인한 사실만 저장합니다. 기존 작업의 새 버전은 기존 조건을 유지합니다.
4. 두 파일 업로드와 서버 검증이 끝나고 등록 완료 안내가 나올 때까지 기다립니다. 전송률 100%만으로 작업이 등록되지는 않습니다.

등록 버전은 **검토 대기**로 시작합니다. 고객의 내용 승인에는 유효한 이용허락이 필요하며, 수납은 최종 다운로드에서 추가 검사합니다. 운영자의 파일 등록이나 수납 확인이 고객 승인을 대신하지 않습니다.

기존 파일과 승인 이력은 덮어쓰지 않습니다. 새 버전은 다시 고객 검토가 필요합니다. 등록 준비 당시 확인한 수정 요청만 처리하며 그사이 최신 버전·요청·지정 승인자가 바뀌면 등록을 거절합니다. 최신 상태를 확인한 뒤 다시 준비합니다.

전송 실패는 새 임시 경로에 다시 올립니다. 일시적인 최종 등록 실패는 기존 예약으로 검증을 재시도합니다. 예약이 만료되면 새로 준비합니다. 새로고침·화면 이동 후에는 파일을 다시 선택해야 할 수 있습니다. 조건만 바꾸려면 **작업 조건 관리**를 사용합니다.

## 실제 영상 확인 순서

자동 검증과 별개로 운영 DB의 실제 계정·영상으로 다음을 확인합니다. 현재 전체 운영 흐름 검증은 완료되지 않았습니다.

1. 운영자로 접근 가능한 고객과 작업을 고르고, 서로 다른 실제 원본·미리보기 두 파일을 전달합니다.
2. 고객 화면에서 작업 조회와 미리보기 재생을 확인합니다. 원본 다운로드는 승인 전 차단되어야 합니다.
3. 고객이 수정 요청을 남기고 새로고침 후에도 요청이 남는지 확인합니다.
4. 운영자가 요청을 확인하고 새 버전을 전달합니다. 새 버전은 검토 대기이고 이전 요청·버전 이력은 유지되어야 합니다.
5. 지정 고객이 최신 영상을 확인하고 채널·목적과 확인 항목을 선택해 승인합니다. 새로고침 후 정확한 버전의 승인 이력을 확인합니다.
6. 실제 수납·권리·접근 조건이 충족된 경우 원본을 내려받아 재생하고 제작 원본과 대조합니다. 다운로드가 SNS 게시 완료를 뜻하지 않습니다.
7. 테스트 범위의 계정에 접근을 회수한 뒤 새 조회·파일 링크 요청이 거절되는지 확인합니다. 다시 허용할 때도 날짜·조건을 명시합니다.

## 파일 처리와 현재 한계

영상은 서명된 주소로 비공개 Storage 임시 경로에 직접 전송됩니다. 서버가 실제 바이트 수·형식·SHA-256을 확인하고 고유 최종 경로로 이동한 파일을 다시 검증한 뒤 DB에 등록합니다. 고객 배정·권한 변경·승인자 변경·업로드·조건 변경은 감사 기록에 남습니다.

자동 영상 변환·워터마크 생성, 50 MiB 초과 파일, 이어 올리기, 중단 파일 자동 정리는 아직 없습니다. 실제 결제 수납·이메일·SNS 게시도 연동하지 않았습니다. Chromium 검증은 격리된 Auth/API/Storage 응답을 사용하며 PostgreSQL 검증은 임시 DB에서 실행합니다. 이 결과를 실제 고객 영상 전달 완료로 해석하지 않습니다.
