# 제작 운영자 사용 안내

운영자는 고객사와 영상을 등록하고 접근·이용허락·수납 조건을 관리합니다. 고객사 `owner`와 별도의 권한이며, 현재 운영자 권한은 포털 전체 고객사에 적용됩니다. 고객의 내용 승인과 실제 SNS 게시는 각각 별도입니다.

## 처음 한 번 설정

1. 별도로 전달하는 비공개 SQL 묶음을 대상 Supabase 프로젝트의 SQL Editor에서 실행합니다. 새 운영자 마이그레이션 `202610160002_operator_uploads.sql`과 첫 운영자 배정이 포함된 설치 단계이며, 코드 배포만으로 운영 DB에 적용되지는 않습니다. 기존 기반 설정은 [Supabase 설정 안내](supabase-setup.md)를 참고합니다.
2. 첫 운영자는 **이메일 확인이 끝난 기존 Auth 계정**이어야 합니다. [운영자 배정 SQL](../supabase/admin/assign-operator.sql)은 해당 계정에 운영 권한을 부여하며 고객사 멤버십을 바꾸지 않습니다. 이미 비활성화한 운영자를 자동으로 재활성화하지도 않습니다.
3. 해당 계정으로 로그인한 뒤 화면 아래 **운영 관리** 또는 `/#manage`를 엽니다. 권한이 없으면 고객 작업 공간으로 돌아가는 안내가 표시됩니다.

운영 화면과 배정 SQL은 Auth 계정·비밀번호를 만들거나 초대 메일을 보내지 않습니다. 실제 이메일·토큰·개인정보를 저장소의 예시나 테스트 데이터에 넣지 않습니다.

## 고객사와 새 작업 등록

1. **새 고객사 등록**에서 숙소 이름, 기존 고객 계정 이메일, 고객 접근 기간을 입력하고 **고객사 등록·계정 배정**을 누릅니다. 이메일이 정확히 하나의 확인된 Auth 계정과 일치해야 합니다. 이 계정은 새 고객사의 고객 측 `owner`로 배정됩니다. 같은 이름의 고객사는 중복 등록할 수 없습니다.
2. **작업할 고객사**를 고르고 **영상 전달하기 → 새 작업 만들기**에서 제목과 **지정 승인자**를 선택합니다. 승인자는 해당 고객사의 활성 멤버 중 접근이 허용되고 이메일 확인이 끝난 계정이어야 합니다. 고객이 실제로 이용할 수 있도록 멤버십 접근 기간도 확인합니다.
3. 파일 접근 기간과 콘텐츠 사용 기간, 허용 채널·목적을 계약 내용에 맞춰 입력합니다. 신규 작업의 기본값은 **접근 미허용·이용허락 확인 전·수납 미확인**입니다. 고객에게 파일 접근을 허용할 시점에 접근 항목을 체크합니다. 이용허락 **확인됨**과 **수납 확인**은 실제로 확인한 사실만 저장합니다. 채널·목적의 초기 선택값은 이용허락을 확인했다는 뜻이 아닙니다.
4. **게시용 원본**과 **별도 검토용 미리보기**를 선택합니다. 각각 최대 **50 MiB(52,428,800바이트)**의 MP4 또는 WebM이며 브라우저에서 읽을 수 있어야 합니다. 검토용은 저용량 또는 워터마크 영상으로 별도 제작합니다. 같은 파일을 이름만 바꿔 선택하면 거절됩니다.
5. 검토용 파일 확인 항목을 체크하고 **두 파일 업로드·작업 등록**을 누릅니다. 업로드 중에는 화면을 유지하고 **서버 검증과 등록 완료 안내**까지 기다립니다. 전송률 100%만으로 작업이 등록되지는 않습니다.

등록한 버전은 **검토 대기**로 시작합니다. 고객에게는 고객사 배정과 접근 조건에 따라 작업이 제공되며, 원본 다운로드에는 해당 버전 승인·수납·접근·이용허락 조건이 충족되어야 합니다. 운영자의 파일 등록이나 수납 확인이 고객의 내용 승인을 대신하지 않습니다.

## 수정본과 조건 변경

- **전달할 작업 → 기존 작업 · 새 버전 전달**을 선택합니다. 기존 지정 승인자·사용 조건·수납 상태를 유지하며 두 파일을 새 버전으로 등록합니다. 기존 파일과 승인 이력은 덮어쓰지 않으며 새 버전은 다시 고객 검토가 필요합니다.
- 미해결 수정 요청이 있으면 내용을 확인하고 반영 확인 항목에 체크합니다. 준비할 때 확인한 요청만 새 버전 등록 시 처리합니다. 그사이 최신 버전이나 수정 요청이 바뀌면 등록이 거절되므로 **새로고침** 후 최신 내용을 확인하고 다시 준비합니다.
- 기간·허용 범위·접근 허용·수납 상태만 바꾸려면 **작업 조건 관리 → 작업 조건 저장**을 사용합니다. 파일 재업로드나 기존 내용 승인 이력 변경 없이 조건을 저장합니다.

전송·등록 오류가 나면 같은 화면에서 **업로드·등록 다시 시도**를 사용할 수 있습니다. 전송 실패는 새 경로에 다시 올리고, 최종 등록 실패는 기존 예약의 서버 검증을 다시 요청합니다. 예약 만료 시 새 예약을 만듭니다. 새로고침·화면 이동 후에는 파일을 다시 선택해야 할 수 있습니다.

## 파일 처리와 현재 확인 범위

영상은 서명된 주소로 비공개 Storage의 임시 경로에 직접 전송됩니다. 서버가 실제 바이트 수·형식·SHA-256을 확인하고 고유한 최종 경로로 이동한 파일을 다시 검증한 뒤 DB에 버전을 등록합니다. 신규 고객사·업로드 예약·버전 등록·조건 변경은 운영 감사 기록에 남습니다. 브라우저가 파일 경로나 서버용 비밀 키를 지정하지 않습니다.

자동 영상 변환·워터마크 생성, 50 MiB 초과 파일, 이어 올리기는 지원하지 않습니다. 중단·충돌로 남은 임시 또는 미등록 파일의 자동 정리도 아직 없습니다. 실제 결제 수납이나 SNS 게시를 자동 수행·확인하지 않습니다.

구현 코드와 격리된 CI 검증은 실제 운영 환경 확인과 구분합니다. 운영자 DB 설치·계정 배정 후 실제 계정으로 고객사 등록 → 두 파일 업로드 → 고객 검토 → 새로고침 후 상태 유지 → 권한에 따른 파일 전달까지 확인해야 합니다. **실제 운영자 업로드의 종단 검증은 아직 완료되지 않았습니다.**
