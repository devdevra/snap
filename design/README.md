## 공통 디자인 기준

- 기준 프레임: 데스크톱 웹 1440 × 1024. 이미지 생성 결과의 실제 픽셀 수와 비율은 `manifest.json`에 기록한다. 완성 이미지가 곧 정확한 CSS 치수나 반응형 구현을 뜻하지 않는다.
- 기존 기획 화면을 실제 이미지 참조로 첨부했다. 숲색 `#254e3a`, 아이보리 `#f4f3ed`, 세이지 `#e9ede2`, 라임 `#d5e89a`을 바탕으로 목재·린넨·자연광이 있는 숙소 이미지를 사용했다.
- 홈·검토함·콘텐츠를 기본 탐색으로 둔다. 한 화면에 핵심 행동 하나와 관련 보조 행동만 배치한다.
- 승인 여부, 사용 가능한 범위, 실제 게시 여부는 각각 표시한다. 다운로드를 게시 완료로 바꾸지 않는다.
- 검토 화면의 승인은 특정 버전에만 적용한다. 사용권 확인과 확인 체크를 마치기 전에는 최종 승인을 진행하지 않는 것이 기본안이다.
- 인물·시설·계절을 고객 실적으로 표시하거나 예약 증가, 가짜 후기, 허위 매출 지표를 넣지 않는다.

## 선택과 다음 단계

초기 고객 테스트의 기준 화면은 **다음 할 일이 선명한 홈**을 권장한다. 납품을 받은 고객이 무엇부터 해야 하는지 알 수 있는지 먼저 확인하고, 콘텐츠 서가와 검토 스튜디오의 장점을 후속 흐름으로 가져오는 방식이다. 이는 디자인 권장안이며 실제 선택은 사용자의 피드백을 따른다.

선택 전에는 UI 구현을 시작하지 않는다. 선택 후에는 [제품 화면 명세](../docs/product-spec.md)에 따라 390px 모바일·데스크톱에서 검토, 수정 요청, 승인 조건, 게시용 다운로드, 게시 응답을 연결한 프로토타입을 만든다. 원본 기획의 `index.html`과 공유용 PDF는 v1 자료이며 이 시안의 구현물이 아니다.

정적 이미지에는 문구·아이콘·배치가 일부 부정확할 수 있다. 가격·기한·권리 판정은 [고도화 기획](../docs/service-plan-v2.md)과 제품 화면 명세를 기준으로 구현 시 정확하게 적용해야 한다. 이 단계에서는 접근성, 모바일 동작, 서버 권한, 실제 파일 전달을 시험하지 않았다.
