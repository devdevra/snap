# Supabase 데이터 기반

**구현 준비 상태입니다. 실제 Supabase 프로젝트는 아직 없고, 이 마이그레이션을 외부 DB에 적용하지 않았습니다.** 현재 포털은 탭 메모리의 가상 데이터로 작동합니다. 아래 스키마와 RPC는 실제 계정·저장 기능을 연결하기 위한 기반이며, 로그인 화면·운영자 관리 화면·미리보기 API는 후속 작업입니다.

## 구조

| 테이블 | 역할 |
| --- | --- |
| `tenants` | 숙소/고객사 |
| `tenant_members` | Supabase Auth 사용자와 고객사 연결, 활성 여부·접근 기간 |
| `assets` | 작업 제목, 지정 승인자, 최신 버전, 계약·권리·수납 상태 |
| `asset_versions` | 업로드한 특정 파일의 버전, 경로, SHA-256, 검토 상태 |
| `version_approvals` | 정확한 버전·승인자·시각·콘텐츠 해시·사용 범위의 변경 불가 이력 |
| `revision_requests` | 특정 버전에 대한 수정 요청과 제작자 처리 시각 |

브라우저의 `authenticated` 역할은 RLS로 허용된 행만 읽습니다. 고객사 멤버십과 파일 접근 계약이 모두 유효해야 작업·버전·승인·수정 이력을 읽을 수 있습니다. 멤버십 목록은 본인 행만 보입니다. 고객사 `owner`도 DB에 직접 쓰거나, 수납·권리·지정 승인자·최신 버전을 바꾸지 못합니다.

고객사·멤버·계약 생성, 수납 확인, 제작 파일 등록은 **별도 신뢰된 운영자 서버**의 책임입니다. 운영자의 인증·권한 확인 API는 아직 구현하지 않았습니다. Supabase 비밀 키를 브라우저에 전달해서 이 작업을 대신하지 마세요. 가입만으로 고객사나 멤버십을 자동 생성하지 않으며, 초대/운영자 배정 흐름을 추가해야 합니다.

## 공개 RPC 계약

세 함수 모두 `authenticated` 역할에서 **실제 사용자 JWT**로 호출합니다. 사용자 ID나 고객사 ID를 입력으로 받지 않으며, `auth.uid()`로 행위자를 판단합니다. `anon`과 서명 서버의 `service_role`에는 실행 권한이 없습니다.

### `approve_asset_version`

입력: `p_version_id uuid`, `p_channel text`, `p_purpose text`, `p_confirmed boolean`, `p_feedback text = ''`.

출력: `{ "approval_id": "uuid", "version_id": "uuid", "approved_at": "ISO 시각" }`.

접근 가능한 최신 검토 대기 버전의 지정 승인자만 승인할 수 있습니다. 명시적 확인, 미리보기 준비, 유효한 권리 날짜·채널·목적, 미해결 수정 요청 없음, 전달된 수정 초안 없음도 확인합니다. 작성 중인 로컬 초안은 서버가 알 수 없으므로 UI가 `p_feedback`을 함께 전달하고 체크 상태를 관리해야 합니다. 수납은 승인의 선행 조건이 아니며, 최종 다운로드에서 따로 검사합니다.

작업 행과 버전 행을 잠근 뒤 승인 이력 생성과 상태 변경을 한 트랜잭션에서 처리합니다. 동일 버전의 중복 승인, 최신 버전 교체와 경쟁하는 오래된 승인 요청은 거부합니다. 승인 이후에는 해당 버전의 파일 경로·해시·버전 식별자를 바꿀 수 없습니다. 새 파일은 새 버전으로 등록합니다.

### `request_asset_revision`

입력: `p_version_id uuid`, `p_message text` (공백 제외 내용 필수, 최대 4,000자).

출력: `{ "request_id": "uuid", "version_id": "uuid", "requested_at": "ISO 시각" }`.

접근 가능한 최신 검토 대기 버전의 지정 승인자가 요청합니다. 수정 요청과 검토 상태 변경은 원자적으로 처리합니다. 작업당 미해결 요청은 하나입니다. 새 버전을 전달할 때 제작자가 기존 요청의 `resolved_at`을 기록해야 새 버전을 승인할 수 있습니다. 이미 승인한 버전의 재편집 발주는 별도 기능이며 이 RPC 범위에 포함하지 않습니다.

### `authorize_asset_download`

입력: `p_version_id uuid`, `p_channel text`, `p_purpose text`.

출력: `[{ "bucket_id": "staycut-deliverables", "object_path": "고객사UUID/작업UUID/버전UUID/delivery.mp4" }]`.

최신 정확한 승인본인지, 미해결 수정 요청이 없는지, 수납·파일 준비·접근 계약·사용 권리가 유효한지 다시 검사합니다. 멤버 중 지정 승인자가 아닌 사용자도 유효한 권한이 있으면 승인본을 다운로드할 수 있습니다. 승인 이력 자체는 권리 만료나 최신 버전 변경 이후에도 보존합니다.

채널 값은 `instagram`, `youtube`, 사용 목적은 `organic`, `advertising`입니다. 날짜는 클라이언트 입력을 받지 않으며 **서버 시각의 `Asia/Seoul` 날짜**, 시작일·종료일 포함으로 판정합니다. 오류 코드는 `42501`(접근 불가), `55000`(현재 작업 상태/계약 조건 불충족), `22023`(잘못된 입력)입니다.

## 비공개 파일과 서명 서버

`staycut-deliverables` 버킷은 비공개입니다. `storage.objects`의 제한 정책이 해당 버킷에 대한 브라우저 읽기·업로드·수정·삭제를 모두 차단합니다. 다른 포괄적 Storage 허용 정책이 이미 있어도 이 버킷은 차단됩니다. 따라서 브라우저에서 `createSignedUrl`을 직접 호출하는 방식도 사용할 수 없습니다.

Vercel `/api/download`가 사용자 JWT로 위 다운로드 RPC를 호출하고, 반환된 버킷/경로만 서버 비밀 키로 서명합니다. 비밀 키로 RPC를 호출해 사용자 권한 검사를 대체하면 안 됩니다. 서명 링크 유효 시간은 60초이며, 발급 후 접근을 철회해도 이미 발급된 링크는 남은 유효 시간 동안 작동할 수 있습니다. 민감한 URL을 로그나 영구 데이터에 저장하지 않습니다.

업로드는 제작자용 신뢰된 서버에서 수행해야 합니다. 파일명은 ASCII 영문·숫자·`_`·`-`·`.`을 사용하고, 경로는 `고객사UUID/작업UUID/버전UUID/파일명`입니다. 버전의 SHA-256을 등록하고 **기존 경로를 덮어쓰지 마세요 (`upsert: false`)**. DB의 승인 이력은 변경을 막지만, 비밀 키로 Storage 파일 자체를 덮어쓰는 운영 실수까지 막지는 못합니다. 미리보기에도 별도의 서버 접근 검사가 필요하며 아직 API가 없습니다.

## 실제 프로젝트에 적용하기

Supabase 프로젝트 생성·프로젝트 연결·환경 변수 설정이 먼저 필요합니다. 이 저장소에는 실제 프로젝트 ID나 비밀 키가 없습니다. 운영 데이터가 있는 프로젝트에 테스트용 `bootstrap.sql`을 실행하지 마세요.

Supabase CLI에서 올바른 프로젝트에 연결한 뒤 마이그레이션 이력을 검토하고 `supabase db push`로 `migrations/202610150001_portal_foundation.sql`을 적용합니다. 실제 Auth·Storage 설정, 프로젝트에 이미 있는 권한/정책과의 통합, 사용자 JWT와 파일로 하는 종단 검증은 프로젝트 연결 후 수행해야 합니다.

## 회귀 검증

`tests/run.sh`는 **CI의 임시 PostgreSQL 16 DB 전용**입니다. 최소 Supabase Auth/Storage 인터페이스를 테스트 스텁으로 만든 뒤 실제 마이그레이션과 회귀 SQL을 실행합니다. `CI=true`, `PGHOST=127.0.0.1`, `PGPORT=5432`, `PGDATABASE=staycut_test` 외 환경을 거부하며, 기존 `auth`/`storage`/앱 스키마가 있어도 중단합니다.

테넌트 간 격리, 익명·직접 쓰기 금지, 지정 승인자, 정확한 최신 버전, 확인/수정 초안, 계약/권리/수납/파일 조건, 수정 요청 처리, 변경 불가 승인/파일 정보, 비공개 Storage 정책을 검증합니다. PostgreSQL 스텁 검증은 실제 Supabase Auth 토큰 발급과 Storage HTTP 동작을 검증하지 않습니다.
