# STAYCUT 고객 포털 프로토타입

사용자가 고른 **최신 홈 시안 2번**(`design/home-editorial.png`)을 기준으로 구현한 반응형 프론트엔드입니다. 상단 탐색·비대칭 사진·큰 제목의 홈에서 검토와 게시용 콘텐츠로 이어집니다.

## 실행

Node.js 22.8 이상에서 저장소 루트 기준으로 실행합니다. 외부 npm 의존성이 없어 설치 단계가 필요하지 않습니다.

```sh
npm run dev
```

개발 서버는 기본 `127.0.0.1:4173`에서 실행됩니다. 컨테이너 미리보기에는 `npm run dev -- --host 0.0.0.0 --port 4173 --strictPort`를 사용합니다. `terminal.local`도 허용합니다. `file://`로 열면 ES 모듈과 파일 다운로드가 제한될 수 있으므로 서버를 이용합니다.

```sh
npm test
npm run build
```

정적 배포 파일은 `dist/`에 생성됩니다. 빌드는 실제 게시나 외부 배포를 수행하지 않습니다.

## 체험할 흐름

1. 홈에서 `영상 검토하기`를 선택합니다.
2. 영상·문구·사용 조건을 확인하고 체크한 뒤 정확한 v2를 승인합니다. 수정사항을 작성했다면 승인 대신 통합 수정 요청을 확인·제출합니다.
3. 콘텐츠에서 최신 승인본을 찾고 샘플 MP4를 내려받습니다. 승인·사용권·접근 기간·수납 조건을 각각 검사합니다.
4. `사용 조건·게시 기록`에서 게시일과 선택 URL을 남깁니다. 다운로드 자체로 게시 상태가 바뀌지 않습니다.
5. 같은 원본의 재편집 가능 여부를 요청합니다. 요청은 추가 제작 확정이나 결제 동의가 아닙니다.

## 범위와 데이터

숙소·주문·승인 이력은 가상 예시입니다. 미디어는 생성한 가상 숙소 사진을 바탕으로 만든 재생·다운로드 테스트용 MP4이며 실제 촬영 영상이 아닙니다. 게시 기록과 요청은 현재 탭의 메모리에만 남고 새로고침하면 초기화됩니다. 실제 고객에게 연락하거나 SNS에 게시하지 않습니다.

이번 구현에는 고객 계정·서버 저장·실제 결제·이메일·SNS 연동이 없습니다. 프론트엔드 판정은 제품 흐름을 검증하기 위한 것이며 실제 서비스의 접근 통제를 대체하지 않습니다. 운영 서비스 전환 시 서버에서 숙소·승인자 권한, 파일 링크와 모든 전달 조건을 다시 검사해야 합니다.

브라우저 검증은 `tests/browser.py`, 화면 비교 및 한계는 `design-qa.md`에 기록합니다. 브라우저 테스트에는 Python Playwright와 Chromium이 필요합니다.
